# Kosen-MCC 設計

このリポジトリの設計と、その決定の理由を記録する。実装の手順と完了条件は `docs/plan.md` に書く。

## 1. 目的

国立高等専門学校機構「モデルコアカリキュラム」（令和 5 年 4 月 28 日版、以下「原本」）の内容を、AI エージェントが参照しやすい形式で完全に整備する。知識の取り出しと確認のための SSOT（唯一の参照元）として使う。

- 利用者は特定しない。教員・カリキュラム設計者、学生・学習者、企業・育成する側のいずれの用途にも中立な、汎用の参照基盤とする
- リポジトリは公開する

## 3. 原則

1. **権威は原本**。リポジトリの内容と原本が食い違う場合は、原本が正しい
2. **正本は 1 か所**。原本の転記は `data/` と `text/` だけに置く。読み物用の Markdown と検索用の索引は正本から生成し、手で編集しない
3. **原文を変えない**。正本には原文をそのまま入れる。要約、言い換え、誤記の修正をしない
4. **原本にない情報は別層**。付加情報は `extensions/` に置き、正本と混ぜない
5. **全ページを対象にする**。234 ページのすべてが、いずれかのレコードか散文ファイルに対応する。例外の範囲を作らない
6. **手で転記しない**。すべての転記は抽出スクリプトで行う
7. **確認の状態を持つ**。レコードごとに、どこまで確認したかを記録する

## 5. データモデル

### 5.1 階層

原本の階層の深さは分類によって違う。

| 例 | 階層 |
| --- | --- |
| Ⅰ 数学 | 大分類 → 学習内容 → 到達目標 |
| Ⅱ-A 物理、Ⅳ-C、Ⅵ-A、Ⅶ-A | 大分類 → 分野 → 学習内容 → 到達目標 |
| Ⅴ-D-1 プログラミング | 大分類 → 分野 → 領域 → 学習内容 → 到達目標 |

領域（3 段目のコード）があるのは Ⅴ だけである。階層が浅い分類には、分野や領域のノードを作らない。空のノードで深さを揃えない。

### 5.2 ノードと ID

すべての階層をノードにして ID を振る。関係データの指し先が、大分類・分野・領域・学習内容・到達目標のどれにもなるためである。

| ノード | ID の例 | 持つ内容 |
| --- | --- | --- |
| 大分類 | `mcc2023:V` | 名称、区分（コア／モデル）、到達水準 |
| 分野 | `mcc2023:V-D` | 名称 |
| 領域 | `mcc2023:V-D-1` | 名称 |
| 学習内容 | `mcc2023:V-D-1:02` | 名称 |
| 到達目標 | `mcc2023:V-D-1:02.03` | 原文、3 列目の種別と内容、注記、ページ、確認の状態 |
| MCC plus の到達目標 | `mccplus2023:AI:01.02` | 同上 |
| 散文の節 | `mcc2023:doc:<位置にもとづく番号>` | 見出し、ページ範囲 |

ID の決まり:

- 接頭辞に版を含める。複数の版を同じ構造で置けるようにするためで、入れるのは令和 5 年版だけである
- コード部分は、原本のコードを半角ローマ数字に正規化したもの（`Ⅴ-D` → `V-D`）
- 番号部分は、その親の中での出現順（2 桁、01 始まり）
- 原本の節番号には重複がある（`2-3.1` が国語・英語・社会の 3 つに振られている）。散文の節の ID には原本の節番号を使わず、位置にもとづく番号を振る
- MCC plus の分野コード（`AI` など）は原本にないので、このリポジトリで定める。定めた対応は `data/` に明記する
- ID は公開の約束事である。一度振ったら振り直さない

「【教育領域の到達目標】」「目標」「学習内容の取扱い」「授業設計の考え方」「一般的な科目名」などの説明文は、それが書かれている階層のノードに持たせる。

### 5.3 到達目標のレコード

```yaml
id: mcc2023:V-D-1:02.03
text: ソフトウェア生成に必要なツールを使い、ソースプログラムを実行できる。
supplement:
  kind: 学習の目安となる項目   # または「キーワード」。様式 1 にはこの項目がない
  raw: プログラムの実行、コンパイル、リンク、エディタ、IDE、ライブラリ、API
  items: [プログラムの実行, コンパイル, リンク, エディタ, IDE, ライブラリ, API]
note: null                     # 「（化学実験と共通）」のような注記
source: {page_pdf: 90, page_printed: 76}
verification: machine          # machine | image | human
```

- 項目名は英語、値は原文の日本語とする
- セル内の改行は紙面の折り返しなので、つないだ文字列を正本にする。原本の改行位置は持たない
- 3 列目は読点で分割して `items` にする。括弧内の読点で誤分割しうるので、分割前の `raw` も残す
- 原本で句点のない到達目標は、句点のないまま持つ
- 到達目標に数式は出てこない（検証済み）。数式用の項目は作らない

3 列目の位置づけは原本で区別されている。「学習の目安となる項目」は授業計画の参考指針、「キーワード」は「必ずしも包含する必要はない」参考である。`kind` でこの区別を保つ。

### 5.4 関係

関係は `data/mcc2023/relations/` に、種類ごとのファイルで持つ。

| 関係の種類 | 指し元 → 指し先 | 追加で持つ内容 |
| --- | --- | --- |
| 複合融合学科で必須 | 配慮事項の行 → 到達目標 | 履修上の配慮、再掲された原文 |
| MCC plus の対応 | MCC plus の到達目標 → 分野 | 原文（「－」は対応なし） |
| 他基準との対応（ABET、JABEE、IEA、CDIO） | 外部基準の項目 → 大分類・分野・学習内容 | 外部基準側の原文、MCC 側の原文 |
| 学習指導要領との対応 | 学習内容 → 指導要領の項目 | 指導要領側の原文、再掲された到達目標 |
| 共通の到達目標 | 到達目標 ↔ 到達目標 | 注記の原文（物理実験と化学実験） |

- 再掲された文は、原文をそのまま残したうえで、対応する到達目標の ID を解決して持たせる
- MCC 側の参照は共通の解決器で ID に変換する。コードと名称の両方で照合し、食い違う場合は解決しない
- 解決できなかった参照は捨てない。原文のまま残し、未解決の一覧に出す

参照の書き方の例:

| 原本の書き方 | 解決先 |
| --- | --- |
| `Ⅲ 人文社会科学` | 大分類 |
| `Ⅳ 工学基礎（Ⅳ-C 情報リテラシー）` | 括弧内の分野 |
| `Ⅰ 数学（確率、統計）` | 括弧内を学習内容の名称として照合 |

### 5.5 誤記

原本の表記ゆれと誤記は `data/mcc2023/errata.yaml` に記録する。正本の原文は直さない。設計時点で見つかっているもの:

- コードの表記ゆれ: 目次は `Ⅴ-D`、本文は `V-D` や `II -C`
- 節番号の重複: `2-3.1` が国語・英語・社会の 3 つに振られている
- CDIO 対照表の 4 番の見出しに「CONTEXT ? THE INNOVATION PROCESS」と「?」が入っている
- Ⅷ の名称が、目次では「基盤的資質・能力」、対照表では「態度・志向性」になっている
- ABET 対照表に「Ⅳ-E グローバリゼーション」が 2 か所ある。目次ではこの分野は Ⅳ-D で、Ⅳ-E は存在しない

### 5.6 散文と図

- 第 1 部、各章の説明文、第 4 部第 2 章、審議過程・委員名簿は、節ごとの Markdown として `text/mcc2023/` に置く。先頭に節の ID とページ範囲を持つ
- 審議過程・委員名簿（PDF 225〜234 ページ）も全文を転記する。氏名と所属は画像照合の対象にする
- 図（画像を含むページは 22）は、画像として切り出し、内容の書き起こしを添える。書き起こしは原文ではないので、その旨を明記する

### 5.7 付加情報

- `extensions/` に置く。全レコードに、作成者、作成根拠、対象の ID を必須にする
- 付加情報から正本への参照は ID だけにする。正本は付加情報を参照しない
- 中身（前提関係、タグ、英訳など）は、正本が完成してから決める。初期の実装では、層の決まりとスキーマだけを用意する

## 6. 抽出

### 6.1 方式

表は、罫線をもとに取り出す（pdfplumber 0.11.11 で検証）。`pdftotext -layout` は、セル内の改行で列がずれるので使わない。

| 抽出器 | 対象 | 方式 |
| --- | --- | --- |
| 到達目標 | 様式 1〜3、MCC plus | 罫線による表抽出。ヘッダー行で種類を判定 |
| 配慮事項 | 複合融合学科への配慮事項 | 同上。再掲された文を到達目標の ID に解決 |
| 学習指導要領 | 第 4 部の 3 列の対照表 | 同上。箇条書きを分割して到達目標の ID に解決 |
| ABET | ABET・JABEE・IEA の対照表（PDF 183〜184） | 表抽出（5 列）のあと、セル内をラベルで分割 |
| CDIO | CDIO の対照表（PDF 185） | 横罫線から行の帯を求め、左右の列を対応づける |
| 散文 | 第 1 部、各章の説明文、巻末 | 見出しで節に分割 |
| 図 | 画像を含むページ | 領域を画像として切り出す |

表のヘッダー行の種類（検証済み）:

| ヘッダー | 表の数 | 使われている場所 |
| --- | --- | --- |
| 学習内容／到達目標／学習の目安となる項目 | 77 | 様式 2（Ⅳ〜Ⅵ） |
| 学習内容／到達目標／キーワード | 13 | 様式 3（Ⅶ〜Ⅸ） |
| 学習内容／到達目標 | 9 | 様式 1（Ⅰ〜Ⅲ） |
| 学習内容／到達目標／学習の目安となる項目／MCC対応 | 4 | MCC plus |
| 学習内容／モデルコアカリキュラム・学習内容の到達目標／高等学校学習指導要領 | 9 | 第 4 部 |
| 学習領域／複合融合学科/コースにおいて必須となる到達目標／履修上の配慮 | — | 配慮事項 |

### 6.2 共通の後処理

- ページをまたぐ表を結合する。後半の表にはヘッダー行がない（59 個）
- ページをまたいで 1 つの行が分断される箇所がある。ページ先頭の行を前ページの最終行と結合する。句点の有無では判定できない
- 結合セルは空で返るので、上の行の値を引き継ぐ
- セル内の折り返しをつなぐ
- ヘッダー行で種類を判定できない表は、自動で取り込まず一覧に出す（説明文中の箇条書きが表として取れる箇所がある。例: PDF 55 ページ）

### 6.3 ページ固有の設定

そのページでしか使えない値（CDIO の左右の境界 x=356 など）は、コードに埋めず `config/` に書く。どのページにどの抽出器と設定を当てたかが、1 か所で追えるようにする。

### 6.4 規模（概算）

| 対象 | 行数 |
| --- | --- |
| 到達目標（Ⅰ〜Ⅸ） | 約 1,200（Ⅰ 76、Ⅱ 152、Ⅲ 43、Ⅳ 44、Ⅴ 754、Ⅵ 96、Ⅶ 16、Ⅷ 16、Ⅸ 6） |
| MCC plus の到達目標 | 約 270 |
| 複合融合学科への配慮事項 | 約 230 |
| CDIO の項目 | 22（うち右列が空のものが 2） |
| ABET の対応行 | 7 |

試作の集計スクリプトによる値で、数件の誤差を含む。合否の基準には使わず、大きなずれを見つける目安にする。確定した値は `build/STATUS.md` に出す。

## 7. 確認

### 7.1 状態

| 状態 | 内容 | 担い手 |
| --- | --- | --- |
| `machine` | 原文が、該当ページの抽出テキストに含まれる | スクリプト（全件） |
| `image` | ページ画像と抽出結果を突き合わせた | エージェント（`page-verifier`） |
| `human` | 人が原本と見比べた | 任意。後から上げられる |

`image` はエージェントの読み取りに依存するので、`human` とは別の状態として記録する。画像照合の記録（対象ページ、実施日、対象の範囲）は `verification-log.yaml` に残す。

### 7.2 画像照合の対象

- ページ先頭の行（行の分断の検出が機械では確実でないため）
- 審議過程・委員名簿の氏名と所属
- ABET と CDIO の全行
- 未解決の一覧に出たもの
- 図の書き起こし

### 7.3 機械検査

- 全 234 ページが、いずれかのレコードか散文ファイルに対応している
- 各レコードの原文が、該当ページの抽出テキストに含まれる（空白と改行を除いて照合）
- ID が重複していない
- スキーマに適合している
- 関係の指し先の ID が存在する
- 生成物が正本と食い違っていない
- リポジトリ内に `/Users/` で始まる絶対パスがない

## 8. 取り出し

専用の検索サーバーや CLI は作らない。ファイルと `rg` で引く。規模が全体で約 1,700 行であり、全文検索で足りるためである。

| ファイル | 中身 | 使う場面 |
| --- | --- | --- |
| `build/goals.jsonl` | 到達目標を 1 行 1 件にしたもの。各行に上位の階層の名称も入れる | 語で探す |
| `build/tree.md` | 全ノードの ID と名称を階層で並べた目次 | 全体像をつかむ、コードから ID を探す |
| `build/relations.jsonl` | 関係を 1 行 1 件にしたもの | 配慮事項、MCC plus の対応、他基準との対応を引く |
| `build/by-field/*.md` | 分野ごとに表の形で読める Markdown | 人が読む、分野を丸ごと渡す |
| `build/STATUS.md` | 件数、確認の状態の内訳、未解決の一覧 | 整備の状況を知る |
| `text/**/*.md` | 散文 | 考え方や定義を引く |

答えるときの決まり:

- ID とページを必ず添える
- 原本の記述と付加情報を区別して示す
- 見つからないときは推測せず「原本に記載なし」と答える

## 9. AI エージェント向け設定（rulesync）

設定のソースは `.rulesync/` だけに置く。`AGENTS.md`、`CLAUDE.md`、`.claude/`、`.agents/` は生成物であり、手で編集しない。生成物はコミットする。利用側が rulesync なしで読めるようにするためである。

### 9.1 `rulesync.jsonc`

| 項目 | 値 |
| --- | --- |
| `targets` | `agentsmd`、`claudecode`、`agentsskills` |
| `features` | `rules`、`skills`、`subagents`、`hooks`、`permissions` |

`rulesync gitignore` は実行しない。

### 9.2 rules（`.rulesync/rules/`）

| ファイル | 適用範囲 | 書くこと |
| --- | --- | --- |
| `overview.md` | ルート | 目的、層の一覧、答えるときの決まり |
| `canonical-data.md` | `data/**`、`text/**` | 原文を変えない、ID を振り直さない、誤記は `errata.yaml` に記録する |
| `extraction.md` | `tools/**`、`config/**` | ページ固有の値は設定に書く、解決できない参照は捨てない |
| `extensions.md` | `extensions/**` | 作成者・作成根拠・対象 ID を必須にする |
| `generated.md` | `build/**` | 手で編集しない |

### 9.3 skills

| スキル | 置き場所 | 内容 |
| --- | --- | --- |
| `mcc-lookup` | 実体は `skills/mcc-lookup/`。`.rulesync/skills/mcc-lookup` はそこへのシンボリックリンク | 問いの種類ごとの引き方、検索パターン、答えの書式 |
| `mcc-extract` | `.rulesync/skills/` | 表の種類の判定、抽出器の実行、未解決一覧の処理 |
| `mcc-verify-page` | `.rulesync/skills/` | 画像照合の手順と記録 |

`rulesync fetch` は、指定したパス直下の `skills/` を探す。外部へ配布する `mcc-lookup` をリポジトリ直下に置くのはそのためである。

### 9.4 subagents

| サブエージェント | 役割 |
| --- | --- |
| `page-verifier` | 画像照合だけを行う。抽出ロジックを見ずに、ページ画像と抽出結果だけを受け取る |

### 9.5 hooks（`.rulesync/hooks.jsonc`）

| イベント | 実行すること |
| --- | --- |
| `preToolUse`（`Bash`） | `git commit` の前に、`user.email` が決めた noreply アドレスかを検査する |
| `postToolUse`（`Write\|Edit`） | `data/`・`extensions/` の編集後に、スキーマ検証と ID の重複検査をする |
| `stop` | 生成物が正本と食い違っていないかを検査する |

hooks と permissions は Claude Code にだけ効く。同じ検査（メールアドレスの検査を除く）を CI でも実行する。

### 9.6 permissions（`.rulesync/permissions.jsonc`）

- `source/**` への編集を拒否する
- `build/**` への直接の編集を拒否する（生成スクリプト経由だけにする）

### 9.7 使わない機能

| 機能 | 理由 |

| mcp | 取り出しはファイルと `rg` で足りる |
| commands | 手順はスキルで足りる |
| checks | 対応ツールに Claude Code が含まれない |
| ignore | 非推奨。permissions を使う |
